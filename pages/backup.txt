        <section id="MCP">
            <h1>MCP Model & Perceptron</h1>
            <div class="paragraph">
                Around 1943, Warren McCulloch (neurophysiologist) and Walter Pitts (mathematician) have a clear
                objective in mind:
                to understand the mechanisms involved in a biological brain and exploit them in AI field.
            </div>
            <br>
            <div class="frow">
                <div class="fcol">
                    <div class="paragraph">
                        They recreated a nerve cell as a binary logic gate
                        <a class="quote"
                            href="https://www.cs.cmu.edu/~./epxing/Class/10715/reading/McCulloch.and.Pitts.pdf"
                            target="_blank">[1]</a>.
                        <br>
                        <span class="underlined" data-tooltip>Dendrites</span> receive multiple signals which enter the
                        cell body; if the accumulated signal exceeds a certain threshold an output signal is sent in
                        output through the axon.
                        <br><br>
                        A few years later <span class="underlined" data-tooltip>Frank Rosenblatt</span> (psychologist)
                        published the first concept of perceptron learning and an algorithm to automatically tune
                        dendrites’ sensibility to make a decision.
                        <a class="quote" href="https://blogs.umass.edu/brain-wars/files/2016/03/rosenblatt-1957.pdf"
                            target="_blank">[2]</a>.
                    </div>
                </div>
                <div class="fcol">
                    <img src="../imgs/neuron.png" alt="McCullochPitts">
                </div>
            </div>

            <hr class="fancyhr hc3">

            <div class="paragraph">
                Consider \(z\) our input function (see the image further on), \(w_j\) the weight associated to an input
                \(x_j\) and let \(\phi(z)\)
                be the activation function.
            </div>
            <div class="paragraph">
                \[z = w_1 x_1 + ... + w_mx_m \]
                \[ = \sum_{m}^{j=0}x_jw_j = w^Tx \]
                \[ \phi(z) =
                \left\{\begin{array}{@{}l@{}}
                1 & \textrm{if $z >= \theta$}\\
                -1 & \textrm{otherwise}
                \end{array}\right.\, \]
                Alternatively, we could consider the activation threshold \( \theta \) already as a weight:
                \[w_0 = - \theta , x_0 = 1\]
                \[z = w_0x_0 + w_1x_1 + ... + w_mx_m\]
                \[ \phi(z) =
                \left\{\begin{array}{@{}l@{}}
                1 & \textrm{if $z >= 0$}\\
                -1 & \textrm{otherwise}
                \end{array}\right.\, \]
            </div>

            <hr class="fancyhr hc2">

            <div class="paragraph">
                In other words, the idea behind both MCP and Perceptron is to use a reductionist approach to emulate how
                a single biological neuron works, which can or cannot propagate an electrical impulse.
            </div>
            <div class="frow space">
                <br>
                <div class="fcol">
                    <img src="../imgs/perceptron.png" alt="Perceptron">
                </div>
                <div class="fcol">
                    <div class="paragraph">
                        The following are the points we must keep in mind when implementing the Perceptron class (see
                        later) to
                        classify a binary dataset:
                        <ol>
                            <li>Initialize \(w_j\) to 0</li>
                            <li>For each training <span class="underlined" data-tooltip>sample</span> \(x^{(i)}\):</li>
                            <ul>
                                <li>Compute output \(\hat{y}\) through
                                    a dot product (<code>net_input(X)</code>) and the activation function
                                    (<code>predict(X)</code>)
                                </li>
                                <li>Update weights \(w_j = w_j + \Delta w_j\)</li>
                            </ul>
                        </ol>
                        What we need now is a <span class="underlined" data-tooltip>learning rule</span> such as \(\Delta w_j = \eta (y^{(i)} - \hat{y}^{(i)}) x_j^{(i)} \)
                        which makes adjustements proportional to input value.
                    </div>
                </div>
            </div>
            <div class="note"> 
                If \(1\) is predicted correctly there is no adjustment to \(w_j\): \[\Delta w_j = \eta(1-1)x_j^{(i)} =0\]
                Otherwise weights are updated towards the direction of the real, correct prediction : \[\Delta w_j =
                \eta(1-(-1))x_j^{(i)} = \eta(2)x_j^{(i)}\]
            </div>
            <br>
            <div class="paragraph">
                If the two classes can be separated with a linear decision boundary, weights will eventually converge to a
                point where no more updates occur (figure).
                In all the other cases, the adjustment of the weights will never alt and we ought to stop the training
                forcibly by setting
                a threshold for the number of misclassifications or a maximum number of <span class="underlined"
                    data-tooltip>epochs</span>.
            </div>
            <div class="grid space">
                <img src="../imgs/iris1.png" alt="Setosa vs Versicolor">
                <img src="../imgs/irisRosenblatt.png" alt="Linear decision boundary">
            </div>

        <section id="Adaline">
            <h1>Adaline</h1>
            <div class="paragraph">
                Now we are going up to examine another mono-level neural network called <span class="underlined" data-tooltip>Adaline</span>
                , presented by Bernard Widrow and his PhD student <span class="underlined" data-tooltip>Tedd Hoff</span> in 1960
                <a class="quote"
                href="https://www-isl.stanford.edu/~widrow/papers/t1960anadaptive.pdf"
                target="_blank">[3]</a>.
                Adeline is particularly interesting because it shows the primary concept of finding
                 the minimum of a <span class="underlined" data-tooltip>cost function</span> which is fundamental to comprehend more sophisticated algorithms. 
                The main distinction between <span class="underlined" data-tooltip>Adeline learning function</span> and Perceptron is that weights 
                are updated starting from a linear activation function instead of a unit-step one.
            </div>
            <div class="frow space">
                <img src="../imgs/adaline.png" alt="Perceptron and Adaline comparison">
            </div>
            <div class="paragraph">
                In Adeline, \(\phi(z) = z \) is computed to tune the weights, 
                while the final classification is predicted by a quantizer (similar to the previous seen unit-step function) as shown in the figure.  
                Thanks to this improvement we can exploit the continuous output to tune our model instead of seeing the world in black or white
            </div>
            <hr class="fancyhr hc3">
            <div class="paragraph">
                One of the most considerable ingredients in supervised ML consists of defining a target function and optimise it during the learning phase. 
                <br>
                Let’s define a cost function to learn weights in terms of <span class="underlined" data-tooltip>SSE</span> between the computed result and the expected label. 
                \[J(w) = \frac{1}{2} \sum_{i}(y^{(i)} - \phi(z^{(i)}) )^2 \]
                <div class="note"> 
                    \(\frac{1}{2}\) is added only to make derivative easier to compute later.
                    <br>
                    The advantage of this function is that it is continuous, differentiable and it is convex,<br>
                     thus, gradient descent method can be used to find which weights minimise the function. <br><br>
                </div><br>
                Thanks to a technique called gradient descent 
                (more <a href="https://www.ibm.com/cloud/learn/gradient-descent#:~:text=Gradient%20descent%20is%20an%20optimization,each%20iteration%20of%20parameter%20updates">here</a>) 
                it’s possible to update our weights by moving away from the gradient \(\triangledown J(w) \).
            </div>
            <div class="frow space">
                <img src="../imgs/gradient-descent.png" alt="Gradient descent">
            </div>
            <div class="paragraph">
                Let's do the math, yay! So, our cost function is generally defined as \(w = w + \Delta w\) and we want to "move away" from the gradient...
                \[\Delta w = -\eta \triangledown J(w) \]
                \[\frac{\partial J}{\partial w_j} = \frac{\partial}{\partial w_j} \frac{1}{2} \sum_i (y^{(i)} - \phi(z^{(i)}) )^2 \]
                \[=\frac{1}{2}\sum_i 2(y^{(i)} - \phi(z^{(i)}) ) \frac{\partial}{\partial w_j} (y^{(i)} - \phi(z^{(i)}) \]
                \[=\sum_i (y^{(i)} - \phi(z^{(i)}) ) \frac{\partial}{\partial w_j} ( y^{(i)} - \sum_i (w_j^{(i)} x_j^{(i)}) ) \]
                \[=\sum_i (y^{(i)} - \phi(z^{(i)}) ) (-x_j^{(i)}) \]
                \[\triangledown J(w) = \frac{\partial J}{\partial w_j} = -\sum_i(y^{(i)} - \phi(z^{(i)})) x_j^{(i)} \]
                This may look similar to Perceptron learning rule but keep in mind that \(\phi(z)\) is a real number and not just a class label.
                Furthermore, weights are updated considering the entire training set instead of incrementing gradually after each sample (this approach is also called
                "Batch Gradient Descent").
            </div>
        </section>

            <h1>Implementations</h1>
            <div class="paragraph">
                <h2>Perceptron</h2>

                <pre>
                    <code class="language-python">
import numpy as np

class Perceptron(object):
    # Perceptron Classifier

    # Parameters
    # eta : float, learning rate (between 0.0 and 1.0)
    # n_iter : int, passes over the training dataset

    # Attributes
    # w_ : weights after fitting
    # errors_ : number of misclassifications in each epoch

    def __init__(self, eta=0.01, n_iter=10):
        self.eta = eta
        self.n_iter = n_iter
                    </code>
                </pre>

                <br>
                Here we simply defined the ingredients of our delicious Perceptron class; 
                note the name convention for <code>w_</code> and <code>errors_</code> which
                reminds to <span class="underlined" data-tooltip>scikit-learn</span> (I'll cover that in the future).
                We also define n_iter to stop the learning process after a certain number of epochs if weights update
                is not converging.
                
                <pre>
                    <code class="language-python">
def net_input(self, X):
    return np.dot(X, self.w_[1:]) + self.w_[0]

def predict(self, X):
    return np.where(self.net_input(X) >= 0.0, 1, -1)
                    </code>
                </pre>
                
                <br>
                See <code>net_input</code> as \(z\) and <code>predict</code> as \(\phi(z)\). Cool part is coming now!
                
                <pre>
                    <code class="language-python">
def fit(self, X, y):
    self.w_ = np.zeros(1 + X.shape[1])
    self.errors_ = []

    for _ in range(self.n_iter):
        errors = 0
        for xi, target in zip(X, y):
            update = self.eta * (target - self.predict(xi))
            self.w_[1:] += update * xi
            self.w_[0] += update
            errors += int(update != 0.0)
        self.errors_.append(errors)
    return self
                    </code>
                </pre>
